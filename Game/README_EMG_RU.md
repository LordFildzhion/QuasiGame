# QuasiGame — событийное управление ЭМГ

## Главное правило

**Одно сокращение мышцы = одно событие = один рывок удочки.** Игра больше не использует непрерывное значение ЭМГ на каждом кадре.

Интерпретатор выдаёт событие со следующими полями:

- `arm`: `left` или `right`;
- `strength`: интенсивность сокращения от `0.0` до `1.0`;
- `seq`: уникальный последовательный номер;
- `timestamp_ns`: время подтверждения события.

Чем меньше нормированная интенсивность сокращения, тем сильнее игровой рывок. В `FishingMechanics.py` применяется обратная зависимость: `hook_power = 1 - emg_strength`. Событие запускает короткий импульс длительностью `fish.reel_impulse_seconds`; пока человек не сделает новое сокращение, новые импульсы не появляются.

## Как устроены части проекта

```text
Game/                         Игровой движок и публичный GameAPI
  API/gameapi.py              Потокобезопасная очередь событий сокращения
  GameEngine/                 Сцена, физика, UI и обработка игровых событий
  main.py                     Создание игры как библиотеки

Bridge/                       Отдельный адаптер между транспортом и API
  emg_game_bridge.py           Отправка событий из SPEED в UDP
  udp_game_bridge.py           Приём UDP и вызов GameAPI

Integration/run_game.py        Точка сборки: GameAPI + Bridge + Game
Bridge/config.py                Настройки UDP; движок о них не знает
Resonance/mulines/             LSL/SPEED и алгоритм обработки ЭМГ
  contraction_detector.py      Поиск отдельных сокращений
```

Игровой движок не импортирует Resonance, LSL, NumPy или UDP. Если позже поменяется источник ЭМГ или транспорт, игровой API не требуется менять.

## Распознавание микро-сокращений

После нажатия Prepare/Start в SPEED интерпретатор сначала собирает **2 секунды покоя**. В это время нужно расслабить обе руки и не двигать датчики. Для каждого канала отдельно оцениваются медианный уровень RMS и робастный разброс шума (MAD).

Детектор использует:

- короткое RMS-окно 20 мс вместо прежних 200 мс;
- порог начала `onset_sigma = 4.0` робастных sigma выше покоя;
- порог отпускания `release_sigma = 1.5` (гистерезис);
- минимальную длительность превышения 20 мс;
- подтверждение расслабления 28 мс;
- защиту от повторного срабатывания 65 мс.

Событие отправляется один раз, когда сокращение завершилось и детектор подтвердил возвращение сигнала к уровню покоя. Поэтому задержка между фактическим сокращением и игровым событием включает длительность сокращения и подтверждение отпускания.

Интенсивность оценивается по пику над шумовым фоном и нормируется в `0..1`. Примерно при 14 sigma выше фона значение достигает `1.0`; более слабые обнаруженные сокращения имеют меньшую интенсивность. Это относительная оценка амплитуды, а не физическая сила мышцы и не MVC.

## Настройка чувствительности

Файл `Resonance/params/speed_configurator.txt`, секция `[event_detection]`:

```ini
calibration_seconds = 2.0
onset_sigma = 4.0
release_sigma = 1.5
min_contraction_ms = 20
release_ms = 28
refractory_ms = 65
full_scale_sigma = 14
baseline_tracking_seconds = 12
minimum_noise_floor = 1e-12
```

Чтобы повысить чувствительность к слабым микро-сокращениям, уменьшайте `onset_sigma` небольшими шагами, например `4.0 → 3.8 → 3.5`, и проверяйте, что при полностью расслабленных мышцах ложных событий нет. Порог ниже 4 sigma на синтетическом тесте уже давал ложные события. `min_contraction_ms` задаёт минимальную длительность; уменьшение помогает очень коротким импульсам, но повышает риск принять шум за движение. Меняйте по одному параметру и после каждого изменения повторяйте покойный тест. Изменения требуют повторного Prepare в SPEED.

**Физическое ограничение:** алгоритм не может достоверно отделить сокращение, амплитуда которого неотличима от фонового шума. В сохранённом в этой поставке отчёте `calib/emg_baseline.json` обе стороны помечены `low_quality`; task-активность по этому старому набору в среднем не превышала уровень покоя. Это не позволяет подтвердить распознавание самых слабых микро-движений на текущей установке. Для научного использования нужно сделать новую запись покоя и серии микро-сокращений на тех же электродах, каналах, усилении и частоте дискретизации, затем оценить долю ложных срабатываний и пропусков. Текущая нормировка `0..1` — относительная амплитуда над шумом, а не ньютон, процент максимального усилия или MVC.

## Запуск

- Полная система: `Start_All.bat`. Подключите источник Native LSL в Resonance, выберите его в SPEED, нажмите Prepare и Start.
- Только игра с тестовыми событиями: `run_game.bat --keyboard`.
- Игра + UDP Bridge без запуска SPEED: `run_game.bat` (игра откроет порт UDP и будет ждать события).
- VS Code: откройте **корневую папку проекта** `QuasiGame_Resonance`, выберите `QuasiGame — Keyboard Test` и нажмите F5. Для работающего SPEED используйте `QuasiGame — Resonance / LSL`.

В тестовом режиме один короткий клик/нажим `Space` создаёт одно событие. Удержание `Space` не генерирует повторы. `↑/↓` изменяют силу тестового события; `Tab` выбирает руку; `T` переключает тестовый и сетевой источник.
