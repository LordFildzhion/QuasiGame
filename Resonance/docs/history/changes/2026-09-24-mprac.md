## Correction: standard services and presets

Removed active `ui/Mprac.qml`, `MpracController.qml`, `Request.qml`, `Tasks.js` and request presets from source, staging and distribution. Their rejected versions were archived under `src/_test-output/mprac-rejected-custom-view-20260924`. Removed the Configurator serviceName extension and the QML Action registration that existed solely for that controller. Configurator is again the stock built-in view and identity. The supported launch-strip path override remains because a restricted set of service/preset launch icons was explicitly requested.

Task launchers open the standard Stimulus console with its task preset (`showUi=true`) and the ordinary NVX and Recorder peers. They reuse idle services and refuse active-session preset changes. The one-shot Python helper applies ordinary parameters/transitions over the existing local R3 EventBus; it has no advertised service identity and creates no custom UI. The bundled Python runtime requires explicitly adding the helper's own directory to its import path; the installed-launcher check caught and corrected this. Its control snapshot reader drains queued historical descriptions before requesting current state.

`stimulusService/recording.cpp` supplies optional, generic recording settings. The normal Start preflights media, applies/readbacks the configured acquisition preset, starts Recorder, waits for connected signal/events/status and fresh samples, then starts presentation. Completion or Stop drains final events and closes Recorder before applying the optional after-acquisition preset. MPRAC selects its full NVX wiring before and Impedance after. Acquisition loss stops the run and retains the error. Recorder already recording is refused. Run-start events retain subject/condition/operator. Closing the Stimulus window waits for cleanup. Other services keep their independent standard controls. Recording remains disabled in the default Stimulus service.
