# P300

The native Qt6 `P300.exe` service owns presentation, classifier training and native feedback. It uses the standard Configurator and existing Recorder; MATLAB model feedback retains the SPEED compatibility path. Source: [src/P300](../../src/P300). Venue presets: [MPRAC](../how-to/mprac.md) and [P300TEST](../how-to/p300test.md).

## Current contract

The standard 6×6 alphabet ends **Э Ю Я ␣ , ⌫**. The space cell inserts an actual space, comma inserts a comma, and backspace removes the preceding Unicode grapheme; empty backspace does nothing. These actions apply only to typing feedback, and each counts as one selection. Command cells render as text even in image mode. The recorded `text_edit` event contains trial, selectedCell, symbol, action and resulting text, alongside the original classifier selection. Existing custom/saved `_ ! ?` alphabets stay literal; old recordings retain their original symbols. [Change and verification](../history/changes/2026-09-27-p300-text-editing.md).

Fresh P300 settings use the P300TEST presentation defaults: primary monitor, fullscreen, standard 6×6 text matrix, 12 letters, five flash cycles, target gap 3 and same-element gap 1, Space pacing on and backup controls hidden. At startup, nominal 100 ms flashes, 50 ms blanks, one-second pre/post-sequence blanks, 5/60-second attention pause and 8/60-second attention half-cycle are rounded to frames using the primary monitor's reported refresh rate (14/7 flash/blank frames at 144 Hz). Saved settings override these defaults; later monitor changes preserve frame counts. The top-right indicator defaults to 60×60 pixels. The initial NVX profile is fully initialized with REF, the eight-channel Q prior and optical timing; selecting Movicom loads its matching prior/firmware timing and hides the optical patch. Automatic calculation after Training is on; combined pretraining still defaults to two letters and accepts any positive count.

- All 53 clinicP300 parameter names and existing mode labels are retained in `parameters.json`. The first three mode choices are **Training**, **Typing**, **Pretraining + Typing**, followed by the existing jumbled/focus modes. Frame-based timings, jitter, matrix appearance and image/background options remain available. **Press to type next letter** now defaults to on: typing waits before its first letter and between letters. Space is the default key and acts only in the active presentation window. The old two main QML files differed in background colour; `background` selects it.
- `ui/Plan.js` creates a bounded, seeded row/column plan; partial rows contain only existing cells. **Timings → Same-element gap** defaults to **1** intervening flash between repetitions of an identical row or column, including cycle boundaries within each letter. Zero retains unrestricted same-group repetition. Each row and column still occurs once per cycle; repeated cycles require the gap to be smaller than the number of groups. Separate letters reset the restriction. **Target gap** remains a distinct constraint between groups containing a known target; it does not apply to ordinary typing. Both constraints hold together. Seeded generation has bounded retries and a valid previous-cycle fallback at tight gaps; it does not promise uniform random permutations. Calibration publishes known targets; feedback requests a result after each letter. Repeated targets beyond one alphabet are generated instead of silently truncating the run.
- Qt's basic render loop keeps the legacy frame-synchronous Flicker and its QML callbacks on the GUI thread. Onset/offset events retain frame-swap host timestamps. This is not a physical display-latency guarantee. Timings are **frames on the chosen display**, not fixed milliseconds at an assumed 60 Hz.
- **Visual → Subject monitor** uses the shared Stimulus automatic placement logic. Monitor choices show physical resolution, reported refresh rate and scaling; previously saved labels without Hz still load. Geometry/DPI/refresh-rate and primary-display changes update placement and conversion readouts. **Indicator position** is beside the trigger indicator's width and height in Visual; there is no separate Scene group. **Timings → Timing basis** shows Hz and ms/frame, and each duration has two editable columns with fixed grey **frames** and **ms** labels anchored at the right inside the fields. Labels remain unit-free. Other numeric units (`times`, `cycles`, `flashes`, `px`, `s`) use the same grey right-aligned in-field decoration, separate from editable values and clipboard text. Editing either field updates the other; milliseconds quantize to the nearest whole frame, and the displayed milliseconds return to that realizable duration. Saved/wire values remain integer frames. If refresh rate is unavailable, only frame editing is available. Repeat/distance/cycle counts are not converted into durations. Changing the monitor preserves the stored frame counts: 6/3 frames means 100/50 ms at 60 Hz but 41.7/20.8 ms at 144 Hz. To retain approximately 100/50 ms at 144 Hz, use 14/7 frames (97.2/48.6 ms), or edit the ms fields. These readouts use the selected monitor's reported refresh rate, not measured optical latency or a dropped-frame correction.
- `screen` selects a QScreen identity. The Automatic option chooses right of primary, then the leftmost screen to its left, then any secondary, then primary. Named selections remain explicit. Geometry includes portrait layouts and negative desktop coordinates. **Full screen** is the single control: it immediately fills the selected monitor, including primary, while checked, and returns to a window when unchecked. It defaults to on. `Primary (explicit)` follows the OS primary display. Old `allowPrimaryFullscreen` and `fullscreenOnRun` IDs remain loadable but are hidden and ignored. `blinkCorner` selects the top-left or top-right optical patch. Backup Start/Stop/Next/Classifier controls are hidden by default in both windowed and fullscreen presentation. Toggle **Presentation controls** (`showControls`) or press **F10** in the presentation window; explicitly enabled controls remain available in fullscreen. Configurator controls remain available. Old serialized default labels still load.
- `fileName` and generic `recordFile` are aliases. The saved filename includes subject and stimulation mode; combined sessions also include training/typing phase. P300 sanitizes the filename leaf for Windows and preserves its directory and `$$$$` numbering template without changing the operator's template. A blank subject uses the selected personal model's identity for typing, otherwise `Anonymous`. Start prepares existing acquisition/Recorder, confirms live samples and recording readiness, then starts presentation. `recordTimeout` provides standalone start/stop padding and the initial combined-session start padding. Standalone recording tails are at least 3.2 seconds and extend for the configured epoch, FIR delay and optical search. The combined handoff instead uses the frozen group recipe’s required epoch/filter/photo tail plus 250 ms transport margin (Recorder minimum 750 ms), and does not add `recordTimeout` before typing. **Amplifier startup** defaults to **Use running amplifier**. **Start if stopped** sends Start to the service named by the EEG address, using its existing settings; it does not stop/reconfigure a running amplifier. P300 Stop/window close/error saves or closes its recording and leaves acquisition running. The old `acquisitionService`, `acquisitionBefore` and `acquisitionAfter` IDs remain loadable but are hidden and ignored by P300. Other Stimulus paradigms retain their legacy preset behavior. P300 reuses the verified recording EEG subscription and attaches the Movicom clock after recording readiness; nonrecorded runs use their own EEG subscription.
- Outputs: `events`, legacy-compatible `Stimulus`, `status`, plus relayed `classified`, `photo_event`, `selected_letter`. **Recording** is the capitalized parameter group. With P300-managed recording enabled, code in `P300Service::prepare` and `StimulusRecording::begin` supplies Recorder’s complete stream list: `recordSource` (all channels in that EEG stream), P300 `events`, `status`, `classified`, `photo_event`, `selected_letter`, and additionally `movicomSyncSource` when firmware synchronization is active. It replaces Recorder’s prior slot list for that run. There are no per-P300-output recording checkboxes. The legacy `Stimulus` copy is not added; inactive outputs can remain empty. Recorder also creates its own `annotations` group. Classifier EEG-channel selection and Configurator viewer visibility do not select recording channels. A manually controlled Recorder, with P300 recording disabled, uses its own stream slots. JSON events carry a unique `runId` and a trial number; stale results cannot select a letter in a later run.
- `classifierFile` selects a native `.p300.json` model or a MATLAB `.mat` model. Native feedback runs in a P300-owned worker without Python/SPEED. **Classifier → Legacy SPEED service / Legacy SPEED stream** apply only to MATLAB model feedback; native models do not use them. MATLAB feedback configures an idle SPEED with `p300/python/online_processing.py`; it never replaces a running task. Scenario errors have an always-visible presentation banner, independent of the hidden backup controls, and remain available as the Configurator Error readout.

**Main → Amplifier** selects NVX, Movicom or Other stream. An explicit NVX/Movicom change selects the EEG address and matching bundled eight-channel group prior/calibration timing; Other stream exposes the custom address. This does not configure the device or replace a personal typing model. Group priors also ship under `p300/classifier/` for use outside the venue. Configure physical channels/montage and firmware sync in the amplifier service. EEG reference is a physical-reference label, not an extra channel or a software rereferencing control. Movicom samples eight inputs against REF; REF/GND are not sampled channels.

## Native classifier calculation

Invoke **Classifier** from Configurator while idle, or use the optional presentation controls. It opens a separate, nonmodal window on Configurator's monitor, using its logical work area for mixed-DPI placement. Without Configurator it prefers a display other than the subject display, then primary. Calculation settings and validation/features have separate tabs. Presentation mode, pretraining length and key pacing remain in Configurator; they are not duplicated in the classifier window. Every classifier input/action has a wrapped tooltip. Clicking an **Available channels** stream copies its channel names, separated by spaces, to the clipboard. Selecting/inspecting recordings does not switch tabs.

Select Resonance HDF5 calibration recordings (or **Use last calibration**), reference and recorded EEG channel names. Subject may be left blank: import uses the recording's identity, or `Anonymous` for an unidentified legacy recording; frozen evaluation can use the model identity. Explicit identity conflicts are still refused. Enter stream group names only when selection is ambiguous. Multiple recordings must belong to one subject and match rate, channel units, reference and matrix. Duplicate paths or identical file contents are refused. A legacy recording without reference metadata relies on the operator's declaration.

**Calculate** runs in a cancellable background worker. Whole-letter leave-one-out validation keeps every flash and cycle of the held letter together; multiple recordings additionally receive leave-one-recording-out validation. Filters run continuously from each recording's processing origin, before epoch extraction. Bad alignment, nonfinite epochs, inconsistent targets and incomplete/repeated row/column sequences reject the entire affected letter. The panel reports accepted/rejected letters, reasons, accuracy by cycle, target/nontarget feature means and EEG availability delay. The final classifier is then fitted on all accepted calibration letters. No parameter search or play-label tuning occurs.

**Save** creates a single portable version-1 `.p300.json`; **Use for typing** selects that saved file. Calculation failure/cancellation retains the previous result and active model. An optional independent-test recording evaluates frozen weights; intended cells may be supplied as zero-based indices in trial order. Unlabelled predictions remain unscored. **Calculate after calibration** uses the last panel settings only after a completed recording has closed; it does not replace the active model automatically. The serialized `trainingOptions` JSON object lets venue presets prefill the panel. Current session subject/reference also reach automatic calculation; a blank subject is filled automatically before recording.

All native presets use class-wise centering, count-pooled covariance with total degrees of freedom `n_target+n_other−2`, and scalar ridge `alpha * trace(covariance)/features`. The score is `weights · features`, with zero bias; cell scores are averaged over their exposures. Complete 3×3 or 6×6 row/column matrices are required. Feature order is channel-major. There is no rereferencing, baseline subtraction or amplitude scaling. Optional adaptive Typing controls cycle count as described below; it does not change model weights or preprocessing.

Feature plots have time/amplitude axes, grid lines, target/nontarget curves and feature markers. Plotted time is `1000 * (start + k*stride + (width−1)/2) / rate` ms: the center of the averaging samples, or the sample time for a point feature. FIR group delay is accounted for in extraction. Recorded V/mV are displayed as µV; unknown units retain their scale. Display conversion does not change classifier features.

### Adaptive Typing

**Timings → Adaptive cycling** is optional and defaults to **off**. **Minimum evidence** defaults to **2 scored cycles** and **Lead threshold** to **1.5**. **Flash cycles** is the maximum in adaptive Typing and the fixed count in Training/pretraining. Parameters include tooltips; cycle units appear inside the fields. The option applies to ordinary native Typing, including the typing phase of Pretraining + Typing. Jumbled/focus modes stay fixed; an explicitly requested adaptive run with a legacy MATLAB/SPEED classifier is refused with a clear message.

The current rule (`cycle-residual-lead-v1`) compares the leading row and column against their runners-up after complete scored cycles. Scores are centered within each cycle/axis. Residual variance around each group's accumulated mean is pooled over `2*(cycles−1)*(matrix−1)` degrees of freedom. Each lead is divided by `sqrt(2*variance/cycles)`; both must meet the threshold, and the leading cell must be unchanged over two cumulative estimates. Flat/tied responses cannot stop. This dimensionless evidence is **not a calibrated probability or a guarantee of accuracy**.

Flashes retain their normal cadence. At a complete physical-cycle boundary, QML may skip future unshown cycles using the latest completed evidence. EEG epoch collection normally makes evidence lag the visible sequence. Native inference validates the request against its own active-trial evidence, then waits for **all already-shown flashes** before deciding. The final winner can differ from the stopping leader. Missing epochs, synchronization errors or invalid cycles still refuse a result; insufficient lead reaches the cycle cap. A minimum at/above the cap simply prevents early stopping.

The existing `events` stream carries frozen `adaptiveCycling` run settings, `adaptive_evidence` messages with scored cycle count/leader/lead/stability/availability, and decision requests with `adaptiveStop`, `evidenceCycles`, and `presentedCycles`. `selected_letter` includes `presentedCycles`, `plannedCycles`, `stopReason` (`fixed`, `cycle-limit`, `decisive-lead`) and triggering `stopEvidence`. No new stream subscription is needed. Native and BPRAC MATLAB replay accept intentional shorter Typing letters only with coherent recorded authorization; ordinary truncation remains rejected.

The learning-only selection study and separately held typing results are in [the adaptive-cycle report](../history/investigations/p300-adaptive-20260928.md). Replay supports optional testing but does not measure changed brain responses or real communication speed. [Native, UI, Recorder and MATLAB verification](../history/changes/2026-09-28-p300-adaptive.md).

### Pretraining + Typing

Select this mode and set **Pretraining letters**. **Number of trials / letters** remains the subsequent typing length. This mode always adapts the group prior selected in the Classifier window using **any positive requested number of letters, default two**. The calculation selector is fixed to group adaptation in this mode, even if a saved panel preset requested full personal training. Ordinary Training retains full subject calibration and the separate adaptation workflow. Pretraining uses known target hints and produces no typed characters or classification requests.

After all requested training letters finish, Recorder closes the calibration file, the background job calculates the model, and P300 saves it beside that recording as `.p300.json` with a non-overwriting suffix if necessary. Only successful calculation with the exact requested accepted-letter count replaces the active classifier. P300 then automatically starts a separate typing recording with a new run ID and processing origin; no Save/Use/Start interaction is needed. The presentation stays on its display during the handoff. Key-paced typing waits before its first letter. There is no manual Save/Use/Start step or added recording padding. Required EEG-tail collection, calculation, save and Recorder readiness still take finite time; this is not a zero-latency promise. Turning key pacing off also makes subsequent typing automatic.

Recording must be enabled. Combined mode automatically adds `$$$$` numbering to the output filename if the operator template lacks it. Subject, reference, complete row/column matrix and frozen group compatibility are checked; automatic calibration also checks the first EEG block against required channel names, units and sampling rate before publishing the processing origin or showing any flash; the group model supplies channels and processing. Stop, including during the save tail or calculation, cancels continuation; failed/rejected calibration or save error preserves the previously active model. Calibration and typing files remain separately importable. Run metadata includes effective `mode` (Training/Typing), requested `sessionMode` and `sessionPhase`.

For the shipped **Movicom 6×6** group model, the pretraining count selects fixed personal/group mixing weights (personal share shown below). Response contrast means the normalized target-minus-nontarget feature mean; covariance captures within-class feature variability/correlation. These statistics are blended separately before recomputing centered Fisher weights with the saved ridge. Ready-made classifier weights are not averaged.

| Pretraining letters | Personal response contrast | Personal covariance | Effect |
|---|---:|---:|---|
| 2 | 50% | 50% | Equal personal/group contributions |
| 3 | 75% | 50% | More personal response contrast |
| 4 | 100% | 100% | Personal classifier from four letters |
| 6 | 100% | 100% | Personal classifier from six letters |

The complementary percentage comes from the group. Four/six retain the selected recipe but contain no group statistical contribution. These are stored corpus-derived policy weights, not confidence estimates or a quality-dependent live switch. Each combined run fits its new calibration recording; it does not accumulate earlier personal sessions or update from subsequent typing. Each calibration letter uses the configured full flash-cycle count. The requested letters are recorded without typed output, then the model is automatically saved and used for typing. The shipped Q/NVX 6×6 prior has different personal contrast/covariance weights: 2 and 3 letters = 50%/50%; 4 and 6 = 50%/25%.

### Processing presets

| Matrix | Preset | Passband and causal filter | Features, 100–600 ms | Ridge |
|---|---|---|---|---|
| 6×6 | Default HP/LP | Butterworth HP order 2, 0.3 Hz; LP order 4, 12 Hz | 40 ms forward means every 20 ms | 0.003 |
| 3×3 | Default HP/LP | HP order 2, 0.1 Hz; LP order 4, 18 Hz | same | 0.001 |
| 6×6 | FIR reference | 0.1–15 Hz, 1023 taps at 500 Hz | point samples every 20 ms | 0.003 |
| 3×3 | FIR reference | 1–15 Hz, 2047 taps at 500 Hz | same | 0.001 |
| 6×6 | Direct IIR | Butterworth bandpass prototype order 2, 0.3–8 Hz | 40 ms means every 20 ms | 0.001 |
| 3×3 | Direct IIR | Butterworth bandpass prototype order 2, 0.3–12 Hz | same | 0.003 |

Every preset includes a causal elliptic anti-alias stage: 20 Hz pass edge, 25 Hz stop edge, 0.1 dB ripple and 60 dB attenuation. The embedded coefficient bank supports 100, 125, 128, 200, 250, 256, 400, 500, 512, 1000, 1024, 2000, 2048, 4000, 4096, 5000, 8000, 10000, 16000 and 20000 Hz. Sample intervals are rounded to the native sample grid; at nonmultiples of 50 Hz the feature grid is approximate. Primary numerical parity covers 500/1000 Hz. FIR length scales with sampling rate and its group delay is included in extraction and decision availability. Advanced settings adjust cutoffs, ridge, window and averaging width; loaded models always retain their serialized settings.

The model stores actual FIR/SOS/anti-alias coefficients, zero initialization, channel names/order/units, rate, declared reference, subject, window/feature layout, synchronization parameters, provenance and validation decisions. Names map explicitly to the incoming channel positions; missing/ambiguous names, changed units/rate, wrong subject/reference or matrix refuse native feedback. Channel metadata absent from the recording appears as `Channel1`, `Channel2`, etc.; no montage substitutions are guessed.

Native synchronization is explicitly selected: presentation timestamps, analogue rising voltage threshold, a rising digital bit, or Movicom firmware echo. Analogue threshold is in the recorded photo-channel units; offset and search length are saved with the model. This native threshold detector is distinct from the MATLAB derivative detector below. Only crossings between two adjacent finite photo samples count; an unrelated invalid photo sample does not erase a later measured crossing, and missing samples are never bridged. Missing edges do not fall back to timestamps. Recorded calibrations and native runs publish `processing_origin` with `firstSampleNs`, identifying the first block used by the zero-state processor. Current source also records `eegBlockCreatedNs` for every timing mode. Import starts at that full block, refusing a missing block or inconsistent first-sample time. For older non-Movicom markers it resolves a unique block with the exact nominal first-sample time, avoiding preceding samples whose reception timestamps overlap the origin; otherwise it retains the older time-trim behavior. Recordings without a marker reset at recording start. [NVX recording check and staged fix](../history/investigations/p300-nvx-avtest-20260927.md). Inference uses the same processor and waits for all required samples. `classified`/`photo_event` message timestamps retain aligned onset; selected results include `availableNs`. Stale runs, invalid cycles, queue overload, EEG disconnection and feedback timeout refuse a result.

### Group typing and short calibration

The Classifier panel accepts explicit **group** models for immediate typing, or **Adapt a group classifier** with any positive requested number of labelled calibration letters (default two). **Use group now** selects the group file and Typing without starting a run. Blank session Subject becomes `Anonymous`; group inference has no training-subject match requirement. Subject-scoped models retain the exact-subject check. Matrix, rate, channel names/order, units and declared reference still have to match; synchronization and all processing coefficients come from the model.

Version 2 `.p300.json` has `scope: group`, an empty recipe subject and `groupPrior`: trace-normalized mean difference, row-major pooled covariance, and source-only selected mean/covariance blend weights keyed by calibration length. Loading checks dimensions, finite values, symmetry, trace normalization, regularized solvability, weight/statistic consistency and blend bounds. Version 1 subject models remain readable; old P300 versions refuse version 2.

Each source subject contributes class-centered, count-pooled covariance with denominator `n_target+n_other−2`. Divide covariance by `v=trace(C)/p` and target-minus-nontarget mean by `sqrt(v)`, then average subjects equally. Adaptation computes and normalizes the same moments from only the first requested complete labelled letters, blends mean and covariance separately with the prior, then applies trace ridge. Predicted targets, later letters and play data never fit the model. The frozen group settings disable processing edits. The manual adaptation count selects how many complete recorded letters to fit; it does not change a standalone presentation. Combined mode uses its own Pretraining letters count for both presentation and fitting.

Saved mean/covariance blend weights at 1/2/3/4/6 letters retain their exact values. Intermediate counts use linear interpolation independently for the two weights. Outside the saved range, the nearest anchor `(n0,w0)` supplies a fixed group pseudo-count `k=n0*(1-w0)/w0`, giving `w(n)=n/(n+k)`; endpoint weights 0 and 1 remain fixed. Derived lengths are an interpolation/extension rule, **not independently validated optimal weights**. Model validation records the rule and actual two weights. Only the requested complete letters participate; later letters remain separate test data. The integer field and planner retain ordinary resource bounds, not a two-/three-letter restriction.

Adaptation creates a subject-scoped version 1 file with calibration-source fingerprints, group provenance and group-model fingerprint. Save and Use remain explicit; failure/cancellation preserves the previous candidate and active classifier. Calibration accuracy is not displayed as validation. Later complete letters in the selected recording appear separately as a frozen-model test. Automatic short calibration checks identity, reference/matrix, requested letter count and Movicom timing mode before recording. Native typing run events record scope, model fingerprint and provenance.

[P300TEST](../how-to/p300test.md) ships separate Q and Movicom learning-only priors. These remain experimental transfer models: source referencing/acquisition and stimulus timing can differ from a new session. Q-derived NVX deployment does not establish equal Q/NVX transfer accuracy. [Separate-play results](../history/investigations/p300-group-transfer-20260927.md), [implementation evidence](../history/changes/2026-09-27-p300-group-classifiers.md).

MPRAC also ships the dedicated `q-6x6-practicum12-group.p300.json`, at 1000 Hz with **Fz C3 Cz C4 P3 Pz P4 PO7 PO8 O1 Oz O2**. Its source Q recordings use **POz in place of Oz**; the other eleven positions match. MPRAC pretraining selects this prior; the global NVX eight-channel profile retains its original model. The dedicated recipe uses causal HP2 0.5 Hz + LP4 12 Hz, 100–600 ms, 40 ms feature means every 20 ms, and 0.3% trace ridge. New nested subject validation scores 380/425 without calibration and 324/339 after two labelled letters, at five cycles. These are source-corpus results, not measured classroom accuracy. [Full protocol, substitution and native checks](../history/investigations/p300-practicum12-20260927.md).

## MATLAB classifier

The existing model contract is retained: 1-based `eeg_chans_inds`, `weights`, `window_size`, `downsampling_factor`, SOS or B/A filter, `which_photo` and photo settings. Optional `sampling_rate` (or `fs`) defaults to 1000 Hz; `fps_time_correction` defaults to the old 60 Hz only for models without a diode. Weights use channel-major, downsampled epoch features. Models must match the actual input count/rate; malformed indices, coefficients or feature lengths are refused.

Analogue alignment uses a median-filtered derivative; optional MATLAB `photo_polarity` is +1 for rising voltage (legacy default) or −1 for falling voltage. Training and online alignment must use the same patch-on edge. Digital alignment uses a rising bit edge. Missing edges or nonfinite EEG refuse the trial, without silently substituting a software marker or inventing a result. Requests wait for actual EEG availability and all preceding flash epochs. Continuous filter state is retained across input blocks. Per-cell scores are averaged by exposure count, removing bias in partial matrices. History is bounded.

The bundled legacy clinic MATLAB model uses EEG columns 1–30 and photo column 32. It is **not** an MPRAC 12-channel model. MPRAC uses native training and the dedicated 12-channel group prior above; its typing launcher preserves the selected model and opens SPEED only for a compatible legacy `.mat`. It no longer points at the absent `mprac12.mat`. Synthetic test models in `_test-output` never deploy.

## Optional Movicom synchronization

Enable **P300 firmware sync** in Movicom before starting acquisition (block size at most 500). In the P300 **Classifier** panel select **Movicom firmware echo**. Closing the panel applies the corresponding **Training: Movicom sync** setting (serialized name `movicomSync`). It selects firmware-clock alignment for Training and the pretraining phase; it does not detect screen light. **Movicom clock source** defaults to `discover:///?stream=sync&name=Movicom`; change it only for a differently named service. EEG and clock must belong to the same acquisition. Native typing automatically uses the timing method saved in its classifier; the training checkbox has no effect on typing and cannot override that model. Existing MATLAB/SPEED feedback retains its previous timing path.

P300 waits for valid paired EEG/clock blocks before starting presentation. It maps frame-swap event timestamps onto the amplifier sample timeline, changing epoch indices rather than merely plot labels. It neither opens USB nor sends a tag for each flash. The [Movicom component](movicom.md#p300-firmware-synchronization) owns D7 exchanges and clock fitting.

When recording is enabled, P300 adds the original `sync` stream to Recorder. A `processing_origin` event stores mapped first-sample time, original EEG block timestamp and clock session/generation. The native model stores `timing: movicom`; training and live inference use the same immutable block mapping and zero-state filter origin. `classified` messages expose both `onsetNs` and `onsetSample`, and never claim a photodiode edge for this mode.

Missing/invalid mappings, wrong device/session, changed generation, discontinuous sample ordinals or backwards mapped time refuse synchronized processing. Loss during presentation stops the run; no fallback to reception timestamps occurs. A silent EEG/clock pair times out after three seconds. Import requires the origin EEG block and all mappings needed for the used epochs; ordinary older recordings cannot acquire firmware synchronization retrospectively. Warmup before the origin and unused recording tail are excluded. Disabled mode preserves the original reception/photodiode paths.

Movicom and live P300 must share the same PC performance-counter time base. Live mapped data more than three seconds old or over 100 ms in the future is refused. Firmware echo does not measure optical onset or remove host-to-device command delay. No unmeasured display correction is added. [Acceptance evidence](../history/changes/2026-09-26-movicom-firmware-sync.md) covers the physical amplifier, live/offline sample and score equality, restart/block-size tests, and injected failures.

The [startup simplification check](../history/changes/2026-09-27-p300-startup-simplification.md) verifies repeated one/three/five-letter software sessions, no amplifier Stop on error/cancellation, 705 unchanged anchor fits, and two combined sessions on a continuously running physical Movicom. All 48 online typing epoch scores and sample indices exactly matched recorded replay. These offscreen workflow tests do not measure optical onset or human classification accuracy.

## Algorithm provenance

The [MATLAB/Movicom comparison](../history/investigations/p300-training-comparison-20260925.md) audits the actual SPEED path and both historical training formulas, and links an offline Python port verified against native MATLAB. The original MATLAB trainer used regularized uncentered second moments; Movicom uses unregularized centered covariance. As of 2026-09-25, `W:/MATLAB/resonance_p300/FisherDA_s4.m` defaults to **class-wise centering with n−1 covariance denominators**, retaining 1% diagonal regularization. Its optional fourth argument `false` restores the original uncentered n-denominator fit. Existing two- and three-argument callers therefore use centered fitting. See the [contract and native MATLAB verification](../history/changes/2026-09-25-p300-centered-s4.md). The study's Mat0/Mat1/Mat2 definitions remain historical and unchanged; the new default has the same weight direction as Mov1, without its normalization or bias.

Both trainers ultimately apply linear scores. Causal IIR training is supported by the MATLAB script; its zero-phase branches are separate offline options. Production training must serialize the complete preprocessing/alignment contract, not just weights and filter coefficients.

Native implementation and acceptance are recorded in [the 2026-09-26 change](../history/changes/2026-09-26-p300-native-classifier.md). Existing MATLAB model loading remains available through SPEED; the native trainer writes the versioned JSON format, not MATLAB files. Movicom firmware synchronization is implemented as the explicit optional mode described above.

### Recording filename ownership

P300 exposes one editable **Recording → Filename template** (`recordFile`). The old Main `fileName` is a hidden synchronized alias for preset compatibility. At Start, P300 adds the subject, mode and combined-session phase, then configures Recorder; Recorder resolves `$$$$` and its output folder. Changing the idle P300 template does not immediately rewrite Recorder. **Recording status** shows Recorder's actual path while recording and retains `Saved: <path>` after a successful save. The base template remains unchanged.

The [2026-09-27 short-calibration review](../history/investigations/p300-short-calibration-20260927.md) found exact live/replay parity but poor group transfer in a new cap session. Corpus averages are not a session-specific reliability estimate; more personal calibration is the practical fallback.
