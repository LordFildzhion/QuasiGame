[driver](../../src/nvx136/nvx136driver.cpp), [configuration](../../src/nvx136/nvx136config.cpp).

## SDK and packaging contract

The active target uses DLL 1.5.21743 from the 2025 kit under `sdk`, with the three FPGA `.bit`
files installed beside it. The older `Dll` directory contains same-name, behaviorally different
libraries. It is still used by the 2021 SDK probe; do not delete it or pair it with the active
executable. The `nvx136_2021` service is excluded from the default top-level build.

The preset JSON is an example, not the only way defaults reach a service. Defaults are in code
so launching through a Configurator or directly has the same starting point. Device-reported
channel counts can differ; choose channels by identity and actual shape, not a fixed array width.

## Lifecycle invariants

1. **Open → `NVXGetVoltages` → configuration.** The voltage result can be discarded, but the
   call itself is required. Controlled cold-hardware comparisons on September 4 isolated it as
   the effective startup step. `NVXGetVersion`, arbitrary reads and delays are not demonstrated
   substitutes. The physical mechanism remains uncertain.
2. Keep the bounded recovery ladder and its diagnostics. `cold_start_pause_ms` exists and defaults
   to 500 ms in the current configuration; it controls retry timing, not the proven first-read rule.
3. Do not query `NVXGetVersion` after starting impedance acquisition. Existing evidence shows
   it stops the sweep while data reads still appear successful. Version fields can report zero
   for failed device transactions even when the SDK call returns success.
4. `NVXSetMirrorTriggers` and the `mirror_triggers` parameter were removed from the active path.
   Do not restore them from old screenshots or a previous SDK proposal.
5. Stop acquisition through the service before closing or terminating it. One service owns a
   physical device. A start failure must not leave a second process competing for the same converter.

## Data and trigger contract

- EEG frame shape is derived from the configured hardware channels and includes status/counter
  words. The public configuration keeps `HardwareOptions::legacyStartSequence` enabled and no
  longer exposes "Disable unused inputs": that path skips `NVXSetChannelsEnabled` and leaves
  hardware channels enabled. Selecting fewer published channels does not imply smaller SDK frames.
  Use the frame-layout helpers and regression tests before changing the retained driver-side
  disabled-channel machinery or startup transactions.
- In impedance mode the SDK buffer is **EEG + AUX + GND**, and GND is at `eeg + aux`, not `eeg`.
  A 128 EEG + 8 AUX device needs 137 words. This is a measured SDK/header discrepancy.
- Publish impedance channels as `kind=Impedance`, `unit=Ohm`; do not let montage EEG types
  relabel them. AUX impedance words are not EEG-electrode readings.
- The current impedance poll interval is 800 ms; a full sweep takes longer. Keep the handling
  of not-yet-measured values and last valid electrode readings. Zero must not become an invented
  perfect reading simply because the sweep has not reached an electrode.
- Trigger output is a byte through `triggerLow`, `triggerHigh`, `triggerPulse`. Parameter values
  and SDK bit placement differ; use the driver conversion. A pending pulse callback is cancelled
  on stop/restart so it cannot act in a later run.
- Counter gaps contribute to dropped-sample reporting. A padded stream must not be described as
  physically lossless. Preserve channel kind/unit metadata and CED applicability boundaries.
- Battery percentage is an estimate derived from voltage; it is not the SDK's verified state of charge.

## Validation route

Use [build](../how-to/build.md) and [testing](../how-to/test.md). Inspect CTest discovery first.

```powershell
ctest --test-dir R:\src\_build -N -R 'Nvx136|nvx136'
ctest --test-dir R:\src\_build --output-on-failure -R '^(test_Nvx136Logic|test_Nvx136Defaults|nvx136_cold_start_recovery_test|nvx136_montage_type_test)$'
```

These named tests use pure logic or a fake SDK. Read [cold-start tests](../../src/nvx136/tests/cold_start_recovery_test.cpp)
and [montage tests](../../src/nvx136/tests/montage_type_test.cpp) before changing the corresponding rules.
The vendor-emulator tests are a separate category: they use a device path and must not run during
acquisition. Frame-layout probes can be switched to real hardware by an environment variable;
inspect their source/environment before running them. Hardware acceptance requires a controlled
cold converter and the appropriate rig, beyond a passing fake-SDK test.
