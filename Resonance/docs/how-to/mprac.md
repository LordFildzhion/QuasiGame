## Venue

The current-build practicum is owned by [src/venues/MPRAC](../../src/venues/MPRAC/README.md) and deployed as `R:\dist\venues\MPRAC`. That README owns the operator sequence, wiring, tasks, recording schema and portability instructions. ## Source ownership

All three P300 presets explicitly set the dedicated recipe: HP2 0.5 Hz + LP4 12 Hz, 100–600 ms, 40 ms means every 20 ms, and 0.3% ridge. The launcher selects the twelve-channel group prior as the active model only when the classifier field is blank, preserving an existing personal/legacy selection. [Default-setting change and checks](../history/changes/2026-09-27-mprac-p300-defaults.md).

- All views and service names are standard: Configurator, NVX, Stimulus, Recorder, P300 and SPEED. There is no venue QML or venue controller service.
- `tools/launch.ps1` establishes venue content paths. `launch.py` opens the ordinary executables and applies presets to idle existing services. `control.py` is a short-lived, loopback-only R3 EventBus client: it does not announce an identity, register a service or create a window. It checks readback, duplicate names and active recordings. An independently running NVX process under another name is refused before another hardware process can be opened.
- P300 launchers apply the EEG preset/start only to a stopped NVX; a running amplifier remains untouched. P300 uses its explicit Amplifier startup policy and ignores legacy acquisition JSON. Its Stop/error does not stop NVX. Task launchers show Stimulus or P300 with the chosen preset and ensure NVX/Recorder are available. Feedback opens SPEED only when the selected classifier is a legacy `.mat`. The typing launcher preserves the selected native/personal model. Presets explicitly retain Automatic subject-monitor placement, the original top-left 10×13 patch, and the 60 Hz schedule (6/3 flash/blank frames, 30-frame pre/post blanks); no local screen geometry or refresh scaling is applied. Start/Stop are ordinary service controls. For Stimulus tasks, optional generic settings in `stimulusService/recording.cpp` own recording preparation and cleanup, including the full NVX wiring preset before acquisition, Recorder readiness and live-sample checks, and final-event drain. Completion/Stop leave NVX in EEG mode; impedance is an explicit launcher action. Media failure refuses before recording; acquisition/recording loss stops the run and leaves acquisition stopped with an error. Reusing idle services applies the selected Recorder preset too, so the filename changes with the task.
- `params`, `protocols`, `stimuli`, `montages`, and `launchbar.txt` are the portable venue payload. CMake stages/installs venues as a distinct distribution subtree. Treat deployed copies as operator content on subsequent upgrades.
- `icons/*.png` distinguish eight task presets within the usual violet Stimulus icon family. NVX uses the standard blue artwork with **12** and **1K**; impedance uses **12** and **Ω**. P300 learning has four rows with one highlighted target cell, matching the height of typing's **AB_** and three-row matrix. BPRAC shares this learning artwork. Recorder retains standard artwork at the same display size. Regenerate with `scripts/render-mprac-icons.py` using development Python/Pillow; deployment requires only the PNGs. CED row 49 names Photodiode on AUX 1, while rows 1–12 retain the cap electrodes. The upper task viewer shows all 14 recording columns. Impedance hides unused physical inputs.
- [import-mprac-legacy.py](../../src/scripts/import-mprac-legacy.py) recreates generated presets/assets from the retired practicum. It is an explicit migration tool, not a build dependency; rerunning it overwrites generated venue files.

The legacy source actually lives at `R:\dist_legacy\PRACTICUMPC`. The old bat files use the assets in `RDUAL/x64/MPRAC_EEG/stimulusPresentation`, which differ from the separate top-level `stimulusPresentation` directory. The import follows the launched QML's relative asset paths. Legacy recordings are read-only parity references.

The user's September 24 replacement image sets supersede matching legacy assets. The 1920×1080 set is installed by default; flat `images-1920x1080.zip` and `images-1920x1200.zip` archives in `stimuli` can be extracted with replacement. Both preserve the supplied PNG bytes.

Checkerboard/button presets configure the lower viewer for photodiode Cut epochs: recording column 13, falling −1.95 V threshold, 600 ms refractory period, −100/+600 ms window and averaging. Only epochs are drawn there, while all raw channels remain above. The lower pane starts collapsed; opening it initially uses 48% of the viewer area, and subsequent collapse/expand restores its adjusted size. This selects one checker inversion polarity per pair. MPRAC uses **Sample order (padded gaps)** continuity: PC timestamp jitter no longer becomes a false gap, while complete missing sample rows still refuse an epoch. The small-checker recording contains an extra optical event. Recheck the threshold on the actual diode/monitor.

P300 presets use the same lower optical-epoch monitor with a 50 ms refractory period for rapid flashes and P300 event markers. The viewer's all-edge average includes hints; it is not a target/non-target classifier. Native classification uses recorded flash labels and the saved optical recipe. Its starting rising −1.85 V crossing is independent of the viewer’s falling −1.95 V monitor; confirm patch-on polarity/level on the on-site rig before training.

## Validation

Build through the normal [build procedure](build.md). Run `test_LaunchBar`, `test_TepExperiment`, `test_TepMedia` and `test_StimulusPresentation` through CTest. [test-mprac.py](../../src/scripts/test-mprac.py) additionally verifies image hashes, CED structure, literal schedules and marker sequences against legacy presets/recordings, then exercises the real UI/services with the test-only `mprac_nvx_fixture.exe` (no vendor SDK). It writes isolated accelerated protocols, recordings and a report under `src/_test-output/mprac-*`; it does not change the operator presets or operate hardware.

Use the bundled distribution Python with h5py/numpy for this harness. The original legacy tree is needed for parity; the installed venue itself does not need it. Physical NVX transport and automatic recording/mode transitions passed on NVX-52 serial 1219 on 2026-09-24. All EEG inputs were invalid/disconnected, the photodiode was absent, and button responses were unverified, so usable EEG and physical onset/response timing remain classroom-rig checks. See the [implementation/evidence record](../history/changes/2026-09-24-mprac.md).

`test-mprac.py --runtime R:\dist --venue R:\dist\venues\MPRAC` checks the installed services; `--real-checker` retains the large checkerboard's 60-second schedule. [test-mprac-launchers.py](../../src/scripts/test-mprac-launchers.py) checks the actual installed batch files, standard names/views, repeated-launch reuse and preset switching. It refuses existing sessions, explicitly launches a device-free NVX fixture, records a short task and stops/closes its own processes. Its unique test recording is moved into its evidence folder. Neither harness launches a physical amplifier.

[test-mprac-hardware.py](../../src/scripts/test-mprac-hardware.py) is a separate, explicit hardware check using the installed services. It requires a detected NVX-52 in the standard NVX service, stopped in `init`, with no existing Stimulus or Recorder session. It opens isolated test copies, keeps the large checkerboard's full schedule, checks channel names/types/units and cue markers in every recording, and verifies retained EEG mode plus manual Stop. It stops NVX through its service before closing test-owned peers; it never kills the amplifier process. Evidence is written under `src/_test-output/mprac-real-nvx-*`. Run only during an authorized rig test; a passing workflow does not establish electrode contact or optical/button timing.

[test-mprac-erp-playback.py](../../src/scripts/test-mprac-erp-playback.py) checks actual lower-viewer Cut counters and visibility using the original legacy files and timestamps, opened read-only. The 2026-09-24 r2 run accepted all 60 large-checker epochs and nine button events in the 45-second prefix, with zero gap refusals. It explicitly opens the otherwise collapsed lower viewer. [P300 verification](../components/p300.md#verification) covers all six legacy modes with synthetic acquisition and synthetic classifier weights. The [follow-up evidence](../history/changes/2026-09-24-mprac-followup-p300.md) separates these checks from physical validation.

[test-mprac-p300.py](../../src/scripts/test-mprac-p300.py) checks the current native venue presets with a private 14-column synthetic source and Recorder. It covers 12-channel optical training/save/use/typing, two-letter twelve-channel group adaptation with automatic typing, model retention, 60 Hz frame values and automatic display selection. It never opens hardware or changes operator services. [2026-09-27 update and evidence](../history/changes/2026-09-27-mprac-native-p300.md).
